## Engine behaviours that matter

Checked in the engine source; changing any of them is a config.yaml edit by a human.

| behaviour | detail |
|---|---|
| Messages sent while the bot restarts are dropped | platforms.telegram.extra.drop_pending_on_cold_boot (default true): on a cold boot the Telegram adapter discards the updates queued while it was offline (plugins/platforms/telegram/adapter.py:3099-3111; log line 'Cold boot: dropping Telegram updates'). A message the owner sends during a deploy restart is lost and has to be sent again; false in config.yaml would replay them. |
| Strangers are ignored | unauthorized_dm_behavior: ignore. The engine default (pair) answers an unknown user with a pairing code. |
| Background skill/memory review is idle | auxiliary.background_review.enabled defaults to true, but a review only fires when the skill_manage tool is loaded or memory review is on (agent/turn_finalizer.py:764-790). The skills toolset and memory are off, so it last ran on 2026-10-28 (the two pending skill proposals; about USD 0.40). |
| Curator | curator.enabled defaults to true: weekly upkeep of agent-created skills only (there are none); consolidate is false, so no LLM call. |
| Context compression | compression.threshold_tokens 100000 since 2026-10-30 18:21 (was 60000: three compactions in six minutes lost the owner's answers). A preflight-compression log line older than the gateway restart shows the old threshold. |
| Telegram command menu | The engine puts at most 60 commands in the Telegram menu and hides the rest (typing them still works). |
| Engine tools besides MCP | Only clarify and vision_analyze are loaded next to the 56 vault_tools tools (latest tool-schema snapshot). tool_call, tool_search, tool_describe, terminal, session_search, skill_view and unprefixed MCP names in old sessions date from 27-28 Oct, before the toolsets were locked down. |
